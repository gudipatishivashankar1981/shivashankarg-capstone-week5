# Software Request and Licensing Procedure

## 1. Purpose and scope

This procedure explains how employees obtain software, which software is allowed, and how Meridian Digital Services ("Meridian") controls licence cost and security risk. It covers installed software, cloud services (SaaS), open-source components and artificial-intelligence tools. It applies to all employees and contractors.

## 2. Pre-approved software catalogue

Software Center lists the pre-approved software catalogue, which includes standard productivity tools, development environments, collaboration tools and approved enterprise AI assistants. Users can install catalogue software themselves, without approval or a ticket. Licences for catalogue software are already funded centrally or allocated to cost centres automatically.

## 3. Requesting non-catalogue software

3.1 How to ask. For anything not in the catalogue, the requester raises a Software Request in ServiceHub. The request must include the business justification, the number of users, the expected annual cost, the type of data that will be used and the proposed owner.

3.2 Approvals. The requester's line manager approves the business need. IT Asset Management checks whether a catalogue alternative already exists. Information Security carries out a security and privacy review.

3.3 Service levels. Requests for software from vendors that have already been reviewed by Information Security are completed within 5 working days of approval. Requests for software from new vendors that need a full security assessment take up to 15 working days.

3.4 Spend. If the software costs more than USD 1,000 a year, the request is passed to Procurement and follows the approval thresholds in OPS-002. No purchase may be made, and no personal or team credit card may be used, until Procurement has confirmed the approval.

3.5 SaaS and click-through terms. Employees must not accept click-through terms, or sign up for a cloud service using their Meridian email address, without an approved request. Free trials that use client or Meridian data are treated as non-catalogue software.

## 4. Local administrator rights

Users do not have local administrator rights by default. Temporary elevation of up to 4 hours can be requested through the privilege management tool for a specific task. Developers who need elevated rights routinely can request them for up to 90 days with manager approval, and the request is renewed at the end of the period.

## 5. Open-source software

Open-source libraries and tools with permissive licences, including MIT, Apache 2.0 and BSD, may be used in Meridian projects without Legal review, provided the library is added to the project's software bill of materials. Software under copyleft licences such as GPL and AGPL requires Legal review before it is used or distributed. Client contracts may restrict the licences a project can use, and the Delivery Manager is responsible for checking them.

## 6. Artificial-intelligence tools

6.1 Principle. The data classification rules in IT-006 decide what may be entered into an AI tool.

6.2 Public AI tools. Consumer chatbots and other public AI services may be used only with Public information. Employees must not enter Internal, Confidential or Restricted data into them.

6.3 Approved enterprise AI assistants. The assistants listed in Software Center have been reviewed for security and privacy, do not use prompts to train models and retain data only as the contract allows. They may be used with data up to Confidential, subject to the client's contract and the need-to-know rule.

6.4 Restricted data. Restricted data, including personal data, credentials and HR records, must never be entered into any AI tool unless Information Security and the Privacy Office have approved a specific system for that purpose.

6.5 Responsibility. Employees remain responsible for the accuracy and appropriateness of anything produced with AI assistance. AI output must be reviewed by a person before it is sent to a client or used in a decision. Code produced by AI assistants follows the same review and testing rules as any other code (OPS-005).

## 7. Licence management

IT Asset Management reviews licence usage each quarter. Licences that have not been used for 90 days are reclaimed automatically, and the user receives a warning 14 days before. A user whose licence has been reclaimed can request it again through ServiceHub. Employees who leave Meridian have their licences reclaimed on their last working day.

## 8. Prohibited software

The following are prohibited on Meridian devices: pirated or cracked software, software that bypasses security controls, peer-to-peer file-sharing clients, personal VPN and proxy tools, cryptocurrency miners, and remote-access tools that have not been approved by Information Security. Software on this list is removed on detection, and its installation is a breach of the Code of Conduct (HR-002).

## 9. Audits and compliance

Vendors audit Meridian's software use regularly. Using software without a valid licence can result in significant fines, so employees must not copy or share licence keys. IT Asset Management maintains the licence register and reports compliance quarterly to the Chief Information Officer.

## 10. Frequently asked questions

How do I get a tool that is not in Software Center? Raise a Software Request in ServiceHub. How long will it take? About 5 working days if the vendor is already reviewed, up to 15 working days if it is new. Who pays? The cost centre owner; anything above USD 1,000 per year goes through Procurement. Can I paste a client contract into a public AI chatbot? No.
